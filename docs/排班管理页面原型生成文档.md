# 排班管理页面原型生成文档

- 版本：V1.0
- 状态：原型设计依据
- 参考：用户提供的「排班管理」界面截图、排班业务确认记录、当前后端 API
- 页面：排班管理（日视图）

## 1. 目标与使用者

页面供排班管理员查看指定日期的轮换安排、生成候选排班、调整人员并核对需求。页面首先要回答：**所选工作日的岗位是否排齐，当前方案能否保存或需要处理例外？**

最常用操作是选择日期、生成/重新生成排班和调整候选排班。排班日期、时段、岗位、组别、姓名和生成状态必须来自同一份数据，不能在右侧统计、日历卡片和排班表中各自写一套样例值。

## 2. 参考图使用原则

沿用截图中的主要布局线索：左侧功能导航、顶部日期导航、中央排班矩阵、右侧当天摘要与统计、底部 A/B 人员和备注区域。截图里的日期、姓名、人数、岗位内容均为示意，不得作为默认真实数据。

当前产品固定时段以 `TimeSlotCatalog` 为准：09:00–11:30、11:30–14:30、14:30–17:30、17:30–19:30、19:30–航班结束、次日 05:30–08:00、次日 08:00–09:00。**不展示旧图中的 04:45–08:00。** 次日时段应明确标记“次日”，条件性 08:00–09:00 交接时段只有在需求数据返回时出现。

“休/维/备勤”是未承担岗位人员的展示列，不代表一个“组休息”班制。系统按上二休二及具体时段呈现实际状态；不要仅凭截图把 A 组整天标成上班、B 组整天标成轮休。负责人/监管人员不是独立岗位名额，而是从候机楼人员中标记的一人。

## 3. 页面结构

### 3.1 全局导航

左侧固定导航宽约 200px，深蓝灰背景，包含：

- 首页
- 排班管理（当前项）
- 排班日历
- 人员管理
- 分组管理
- 岗位设置
- 排班规则
- 统计分析
- 历史记录
- 系统设置

底部放当前登录管理员的姓名、角色和账户入口。原型可使用中性演示身份；不能暗示已接入真实认证或权限系统。

### 3.2 页面标题和日期选择

主内容标题为“排班管理”，副标题简述“按轮换规则生成并调整候选排班”。标题行右侧放真实可用的操作：导入历史排班、生成排班、更多操作。未接后端的操作应标注为演示或禁用，不能显示成功后却没有保存。

标题下方为月份切换器和横向日期条。日期项至少区分：选中日期、今天、工作日、休息日、已有候选排班、已发布排班、生成失败。工作日/休息日按照二上二休日历计算；用文字和图形标记，不只用颜色区分。左右切换月份和日期条滚动不应改变已选日期。

### 3.3 当天摘要和排班操作

排班主面板标题例如“10 月 17 日排班”，旁边显示清晰状态：未生成、候选已生成、已编辑未保存、已发布或生成失败。另显示候选版本、最近生成时间、当天早下组/晚下组。组别摘要以轮换规则为准，不将不同时间段的组别压缩成整天一个“上班组/休息组”。

右侧按钮：

- **生成排班**：没有候选时生成。
- **重新生成**：存在候选时使用同一按钮位置；二次确认说明会覆盖当前未发布候选和手动修改。
- **调整排班**：进入编辑态，可调整人员分配。
- **保存调整**：校验成功后保存候选。
- **发布排班**：仅在候选有效且无未保存修改时可用；当前后端没有发布接口，接入前需显示为演示按钮或禁用状态。

生成失败时保留用户正在看的排班，明确列出不可行原因；不得用空表覆盖已有候选。重新生成只替换当前日期最新候选，不影响已发布版本。

### 3.4 排班矩阵

桌面端为中央主要区域，表头固定，时段列固定在左侧。岗位列按截图的业务顺序展示：

| 列 | 显示内容 |
| --- | --- |
| 时段 | 起止时间；跨日项附“次日”标记 |
| 打饭 | 该时段打饭人员，固定 2 人 |
| 过夜 | 过夜轮换人员；展示轮换顺序或顺序号 |
| 防爆 | 防爆人员；人数标签显示需求范围 |
| 负责人/监管 | 候机楼负责人姓名；明确标为“监管”，不重复计入岗位人数 |
| 候机楼 | 该组除防爆、夹层及同段其他岗位后剩余的候机楼人员 |
| 夹层 | 夹层人员，按需求配置 1 人 |
| 回流/拉包 | 回流人员；标出常规时段或夜间人数需求 |
| 休/维/备勤 | 当段未承担上岗任务的人员，按实际排班结果展示 |

每个人员以姓名为主，可辅以姓氏色标或稳定头像缩写；同一姓名在不同岗位必须保持一致识别。人员标签可显示必要的限定标记，例如“仅防爆”“监管”。鼠标悬停或键盘聚焦显示组别、资格和限制原因。空岗位用“—”和可读状态表示；缺少需求与需求人数为 0 要区分。

编辑态在人员标签旁提供移除操作，岗位单元格内提供“添加人员”。添加候选只显示该日期有效、已启用且符合该岗位资格的人员；候机楼人员资格按剩余在岗人员规则处理，不要求单独的候机楼资格。无资格人员应解释原因，不要仅从列表中静默消失。

表格不允许同一人员在同一时段出现在两个岗位。变更后即时显示待保存状态和校验结果；不合法时保留原值或明确标记冲突，不能静默丢弃。

### 3.5 右侧信息栏

截图右栏分成紧凑、语义明确的区块：

1. **今日概览**：排班日期、工作日/休息日、早下组/晚下组、覆盖人数、岗位需求满足情况和时段数量。人数、总岗数必须由排班数据计算。
2. **轮换提醒**：列出即将需要关注的岗位轮换或资格覆盖不足。只展示能从真实历史数据或规则计算得到的提醒。
3. **岗位次数统计**：可选择最近 14 天等范围，展示每个人在不同岗位的次数；统计对象和日期范围写清楚。当前后端没有区间统计接口，接入前使用明确标注的演示数据或隐藏此区块。
4. **快捷入口**：人员管理、分组设置、岗位设置、排班规则。入口应导航到真实页面；不存在页面时标为原型链接。

右栏在较窄屏幕下移动到主排班表之后，不得挤压排班矩阵到无法阅读。

### 3.6 组别人员与备注

排班表下方并列展示 A 组和 B 组人员名单，并按所选日期显示组别成员和上二休二周期状态。该卡片用于核对人员，不重新计算或覆盖表格中的时段任务。备注区展示排班备注和轮换交接信息，编辑入口只在备注可保存时启用。

## 4. 已确认的排班规则

### 4.1 硬性规则

- A/B 两组按上二休二运行；早下/晚下由已配置的轮换锚点解析。示例：12 日 A 早下、13 日 B 早下；16 日 B 早下、17 日 A 早下。
- 每段岗位需求属于一个组，不能跨组混排；同一人员在同一时段不能同时站岗和接飞机/承担另一岗位。
- 防爆每段至少 3 人，可多于 3 人。只有具备防爆资格者可安排；廖家史配置为仅防爆，莫少波不具备防爆资格。此类限制来自人员资格/可用性数据，原型不得按姓名硬编码。
- 夹层每段 1 人，按夹层资格筛选。
- 每次打饭 2 人，并从该时段无需承担其他上岗任务的人员中安排；优先考虑有防爆资格者，但不得因此造成同段重复上岗。
- 常规时段回流 2 人，来自当段轮休组；19:30–航班结束回流例外，只需 1 人，并从当段轮岗组安排。回流人员同一天各段不重复。
- 过夜由当天晚下组安排 2 人，按“接广州”既有顺序轮流；原型只呈现配置/计算出来的顺序，不自行发明轮换起点。
- 候机楼人员是该段同组人员扣除防爆、夹层及其他已安排岗位后的剩余人员。每段从候机楼人员中选 1 名监管人员；监管人员当天不重复。负责人还需承担隔离区巡岗，不能与门口岗位并行分配给同一人。
- 若工作日第二天早下，休息日第一天需安排 05:30–09:00 交接后再休息；公平优化时尽量避免该交接。时间段由已配置的 05:30–08:00 和条件性 08:00–09:00 需求表达。

### 4.2 公平性优化目标

公平性主要比较每个人在不同岗位的**分配次数**，不按工时作为主要指标，因为各时段固定。尽量避免同一个人在同一工作日的多个上岗时段连续重复承担同一岗位；“连续同岗位”是按时段逐次比较，不是跨时段连续工时。减少休息日清晨交接也属于优化目标。上述公平和偏好不应显示为硬性违规，除非对应规则明确设为硬约束。

## 5. 交互流程

### 5.1 选择日期并查看排班

1. 选择某日，更新日期标题、轮换摘要、人员名单和排班表。
2. 根据工作日/休息日状态显示可执行操作。
3. 工作日没有候选时显示空状态及“生成排班”主按钮；休息日不显示普通工作日生成提示，但有条件交接时显示对应安排。
4. 已存在候选时可查看、调整或重新生成；已发布记录只读。

### 5.2 生成候选排班

调用 `POST /api/schedules/generate-from-database`，请求：

```json
{"scheduleDate":"2026-10-17"}
```

成功后用响应中的 `scheduleId`、`version`、`assignments` 更新当前视图，并提示“候选排班已生成”。`INFEASIBLE` 时显示 422 返回的业务原因，保持页面已有内容。点击重新生成需说明会覆盖当前日期最新候选；生成成功后候选 `scheduleId` 和 `version` 沿用。

### 5.3 手动调整候选

使用 `GET /api/schedules/{scheduleId}` 读取已保存排班；编辑后调用 `PUT /api/schedules/{scheduleId}`。提交的是完整岗位分配，人员用数据库 ID。监管人员通过 `terminalSupervisorId` 指定，不能作为额外人员重复计数。保存前显示本次变更摘要；取消编辑恢复最近一次已保存的候选。

### 5.4 发布、导入、导出

截图包含发布、导入历史排班和更多操作，但当前后端尚无发布、历史导入或 Excel 导出 API。原型可以表现这些入口；真实接入前需禁用或标为“仅演示”，不得伪造持久化成功。发布需在后续后端接口明确状态转换、发布后只读和轮换状态更新规则。

## 6. 页面数据模型

原型使用一份统一数据对象驱动日历、摘要、矩阵和右栏：

```ts
type ScheduleDay = {
  scheduleDate: string;
  dayType: "WORKDAY" | "REST_DAY";
  status: "EMPTY" | "CANDIDATE" | "PUBLISHED" | "INFEASIBLE";
  scheduleId?: number;
  version?: number;
  earlyDownGroup?: "A" | "B";
  lateDownGroup?: "A" | "B";
  assignments: Array<{
    slotCode: string;
    slotLabel: string;
    slotSequence: number;
    positionCode: string;
    positionName: string;
    groupCode: "A" | "B";
    people: Array<{ id: string; name: string; terminalSupervisor: boolean }>;
  }>;
  generatedAt?: string;
  note?: string;
};
```

人数统计、岗位满足状态和分组人数必须从 `assignments`、日期需求及人员列表计算，不能另存互相矛盾的副本。界面展示姓名，提交时保留 person ID。候机楼监管人员沿用 `terminalSupervisor` 标记。

## 7. 视觉与响应式要求

- 以截图为基础：深蓝侧栏、浅灰蓝工作区、亮蓝主操作、白色内容表面；不用渐变背景和大面积装饰。
- 角色颜色固定且低饱和，颜色只作辅助，岗位名、姓名和状态文字必须同时可读。红色只用于冲突/失败，避免把所有岗位做成彩虹色。
- 采用紧凑但可读的数据表：约 14px 表格正文、12–13px 次级说明；姓名完整显示或使用可访问的省略提示。
- 约 1440×900 桌面优先；侧栏约 200px、右栏约 280–320px，主表获得剩余宽度。排班表表头和时段列可固定，内容过宽时仅表格区域横向滚动。
- 641–1100px 折叠侧栏、将右栏移到主内容下方；窄屏将每个时段改为可滚动的岗位分组卡片，保留全部岗位、人员和状态，不让整页横向滚动。
- 所有按钮和日期选择器支持键盘焦点；颜色对比符合可读性，点击目标至少 44px 高。岗位冲突同时使用文字和图形标记。

## 8. 状态与反馈

原型必须覆盖：首次未生成、加载中、生成成功、无可行排班、网络/接口错误、编辑未保存、保存中、保存失败、已发布只读、无条件交接、暂无统计数据。

- 加载时保留表头和布局，不跳动或全屏遮挡。
- 局部接口错误显示在对应区块，提供重试；不把 API 堆栈直接展示给管理员。
- 未生成和统计为 0 是两种状态；无数据不能伪装成 0。
- 关闭编辑或切换日期前，若存在未保存修改，提示保存、放弃或取消离开。
- 调整人员后即时显示“待保存”和硬规则校验；保存成功后显示新的更新时间。

## 9. 当前 API 映射与待补能力

| 页面能力 | 当前接口/状态 | 原型处理 |
| --- | --- | --- |
| 查询指定日期岗位需求 | `GET /api/schedules/{date}/requirements` | 正常接入 |
| 生成或重新生成 | `POST /api/schedules/generate-from-database` | 正常接入；同日重生成覆盖最新候选 |
| 查看已保存排班 | `GET /api/schedules/{scheduleId}` | 用生成响应中的 ID 查看 |
| 编辑候选人员 | `PUT /api/schedules/{scheduleId}` | 提交完整 assignments |
| 按日期重新打开最新候选 | 当前无按日期获取最新排班接口 | 建议补 `GET /api/schedules/{date}` 或候选列表接口；首版原型可在路由状态保留 scheduleId |
| 发布排班 | 当前无接口 | 禁用/演示；后续设计发布与状态更新接口 |
| 导入历史排班 | 当前无接口或导入格式 | 展示文件选择原型，不宣称写入成功 |
| Excel 导出 | 当前无接口 | 仅展示入口，不生成伪文件 |
| 近期岗位统计/轮换提醒 | 当前无统计区间接口 | 以明确演示数据展示或隐藏；上线前补统计接口 |

## 10. 原型验收清单

- 可选日期清楚显示工作日、休息日、今天和所选状态；二上二休与早下组信息不混淆。
- 所有固定时段正确，跨日时段标“次日”，不出现 04:45–08:00。
- 负责人被标记为候机楼监管人员，不多算一个岗位名额；未安排人员和休息日状态表达准确。
- 防爆人数标签为至少 3 人；夹层、打饭、回流/过夜数量遵守对应时段需求。
- 重新生成提示覆盖范围；生成失败保留已有候选；修改需要显式保存。
- 编辑时能添加/移除人员、指定监管人员，并呈现组别、资格、重复上岗及人数校验结果。
- 发布、导入、导出和统计等未接接口的入口有清晰演示/禁用说明。
- 1440px 下主要排班内容易扫读；窄屏无需整页横向滚动；空、错误、加载、未保存状态均可辨认。
